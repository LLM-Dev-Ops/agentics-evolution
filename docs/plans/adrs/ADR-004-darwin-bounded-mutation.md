# ADR-004: Darwin bounded mutation

- **Status**: proposed
- **Date**: 2026-08-11
- **Tags**: darwin, mutation, sandbox, safety

## Context

Hypotheses must become testable harness variants without granting an optimizer permission to edit its own safety controls, evaluators, or release authority.

## Decision

Use `@metaharness/darwin` as the sole candidate-generation engine. Agentics supplies a proposer adapter and an allowlisted `MutationContract` per enrolled repository.

### Mutation contract

The default surfaces are Darwin's planner, context builder, reviewer, retry policy, tool policy, memory policy, and score policy. Repositories may narrow this set. Expansion requires an accepted ADR, updated threat model, and new anchor coverage.

Immutable paths include:

- safety rails and mutation contracts;
- evaluators, anchors, holdouts, scorers, and promotion rules;
- CI/release configuration and CODEOWNERS;
- credentials, organization policy, receipt keys, and ledger state;
- dependency manifests unless a specific dependency campaign is authorized.

### Execution

- Candidate work runs in an ephemeral isolated worktree/container with no inherited secrets, no shell, no ambient network, read-only source snapshot, bounded writable overlay, CPU/memory/time/PID quotas, and an explicit tool capability set.
- `inspectVariant` and `validateGeneratedCode` run before execution. A violation creates a rejected archive record and never reaches an evaluator.
- Each generation mutates one approved surface by default. Concurrency is bounded by the policy envelope and usage reservation.
- Every candidate records parent digest, mutation target, seed, proposer/model, prompt digest, source snapshot, tool grants, runtime image digest, and cost.
- All candidates, including rejected variants, remain in Darwin's archive and the content-addressed artifact store.

### Integration

Ruflo ADR-322B's Darwin proposer pattern is the adapter reference. Agentics execution-engine owns isolation; Darwin owns mutation/search semantics. The adapter translates outcomes without re-scoring them.

## Acceptance criteria

1. Attempts to touch protected paths, use symlinks, access environment secrets, spawn a shell, or access an unapproved network endpoint fail before evaluation.
2. The same snapshot, seed, config, and deterministic proposer produce the same archive.
3. Killing a worker cannot corrupt the parent or another candidate.
4. Budget exhaustion stops cleanly and produces a resumable archive.
5. Concurrency never exceeds the granted envelope under stress.
6. Every generated byte is attributable to a candidate and parent.
7. No candidate can modify the evaluator or its own score.
